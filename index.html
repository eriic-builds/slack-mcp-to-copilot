What this guide does, and what the lab demonstrated

A guided evaluation using Slack's hosted MCP server and Microsoft's custom federated connector. No local server, Bolt app runtime, or Teams bot is required. This file configures nothing automatically: work in the linked admin portals and record your own results.

In the source lab, an independent diagnostic identified disabled app-level Slack MCP access as a blocker. After that access was enabled, the operator confirmed Slack tools were listed and reported successful Copilot retrieval. The workspace was reported to be on Slack Free; that observation is not a universal entitlement guarantee. Citation accuracy, freshness, cross-user isolation, token refresh, and revocation behavior were not separately confirmed. Customer checkpoints start unchecked: validate your own tenant before production use.

01
Documented requirements + lab choices

Confirm the route and the two identities

Use a Microsoft admin account in to configure the connector, and the pilot account to use it. The same person must also authorize the intended Slack account; do not assume matching email addresses automatically connect the identities.

  1. In Microsoft 365 admin center, confirm the displayed tenant before making changes. Setup requires a Global Administrator or AI Administrator. The pilot user needs a Copilot license under the current federated-connector guidance.
  2. Confirm app-creation/installation rights in , and access to Teams Developer Portal in the Microsoft demo/pilot tenant.
  3. Search Copilot > Connectors > Gallery for Slack. A Microsoft-published federated Slack connector is documented, but tenant availability can differ. If available, inspect that supported route before deciding custom setup is necessary.
What federated means: live retrieval, not a crawl/index of Slack into Microsoft 365. Retrieved text still enters Copilot processing and can appear in responses and conversation history. Do not describe this as "data never leaves Slack."
Why a Teams-branded portal for a Copilot connector?

Microsoft's custom federated connector documentation explicitly uses the Teams Developer Portal to register OAuth and a Teams-domain callback to complete sign-in. These are shared authentication services. You are not creating a Teams bot or installing a Teams app.

Source: custom federated connectors, OAuth 2.0

02
Slack / internal app identity

Create or reuse an internal Slack app

  1. Open Slack app management. At the upper right of Your Apps, click Create New App.
  2. In Create new app, under From a template, click the Starter app tile, then Continue at the bottom right. Do not select AI agent or use the coding-agent prompt on the right.
  3. In the following setup screens, enter in App Name and select in Workspace. Click Continue when offered. At Review your app, review the settings and click Create. If a no-scopes warning appears, Create Anyway creates the registration without those optional capabilities; the required user scopes are added in task 03.
  4. If Slack displays Install to Workspace or an access-consent page, review the template's requested permissions before proceeding. The required user OAuth consent occurs in task 06; installing a starter bot does not complete it.
  5. When app settings opens, select Basic Information in the app's left sidebar. In App Credentials, copy the App ID and non-secret Client ID into this guide's task values. Keep the Client Secret in Slack until the direct portal-to-portal copy in task 04.

This path matches the supplied Starter app screen. Slack's written quickstart also documents a Pick features > Continue path; older screens may say From scratch. These are alternative entry paths, not extra buttons to click after Starter app. If a later screen differs, use its app-name, workspace, and review controls rather than installing development tools. Existing-app users can open their app directly and start at Basic Information.

Open your Slack app settings (personalized after entering a valid App ID)

Enable the app for Slack MCP server access

In the app settings, open the Agents & AI / assistant settings page and review the control for Slack MCP server access. Enable that access for this internal app, and complete any required approval or reinstallation after reviewing changes. Page labels can vary; do not assume creating an app or adding OAuth scopes automatically enables MCP.

Open your app's MCP / assistant settings (uses your App ID and the /app-assistant settings path)

Observed prerequisite: a direct Slack MCP initialization returned HTTP 400 / JSON-RPC -32600: App is not enabled for Slack MCP server access. Slack directed the app owner to its /app-assistant settings page. A valid user token and the three correct scopes alone did not pass this gate. This requirement does not mean you need to run a Bolt bot or build an agent response loop.

Skip the Bolt starter prompt for this goal. It scaffolds a bot/app running inside Slack. Bot tokens and app-level Socket Mode tokens are not the credentials used by this per-user hosted-MCP connection. No plugin install, CLI login, or VS Code project is needed to attempt this route.

Slack currently permits its hosted MCP for internal apps and Marketplace-published apps, not unlisted distributed apps. A customer's own internal registration is different from distributing one app across unrelated customers.

03
Slack / OAuth & Permissions

Configure redirect and read-only user scopes

In , open OAuth & Permissions > Redirect URLs. Add the exact value below and select Save URLs.

Scroll to User Token Scopes, not Bot Token Scopes, and add these three scopes for this public-channel pilot:

User scopePurposeCopy
search:read.publicSearch public-channel content in the authorized workspace.
channels:historyRead public-channel messages and threads.
channels:readDiscover public channels and related metadata.
This is not a one-channel permission boundary. Public search can cover public channels across the user's authorized workspace, even channels the user has not joined. Naming in prompts is a test filter, not an access-control policy. Use an isolated lab or an explicitly approved pilot workspace.

Do not add private-channel, DM, file, or write scopes for this baseline. Existing Bolt bot scopes do not substitute for user scopes. A yellow "reinstall" banner means scope changes are not yet granted to existing installations/tokens: finish this configuration first, then review and complete any required install/reinstall and the pilot user's OAuth consent before testing. Do not assume saving scopes grants access.

For each scope, click Add an OAuth Scope inside User Token Scopes, type the exact scope name, and select the matching result. Repeat three times. If Slack requires installation now, use Install to Workspace or Reinstall to Workspace, verify the intended workspace and scopes, then approve only after review. Do not copy any issued tokens into this guide.

PKCE and token rotation: avoid an accidental irreversible change

This guide mirrors an initial confidential-client, client-secret test with PKCE off. Microsoft's custom-connector guide makes PKCE optional; Slack's metadata advertises S256 support. Slack's separate "enable PKCE" app setting changes the app to a public client and is one-way without Slack support. Do not toggle it or enable token rotation blindly. For a production pilot, agree the OAuth security model with the responsible administrators and verify the resulting exchange.

04
Microsoft / OAuth registration

Tell Microsoft how to sign users into Slack

In Teams Developer Portal, sign into . Select Tools > OAuth client registration > New OAuth client registration (also labeled "New OAuth connection" in some versions).

Portal fieldYour valueCopy

Client Secret: enter it directly from Slack Basic Information > App Credentials. This guide intentionally has no field to collect it. The secret is not your bot token or app-level token.

Scope formatting: this Microsoft portal field expects comma-separated entries, so copy search:read.public,channels:history,channels:read. Do not paste the space-delimited OAuth wire-format list into a field whose help text requires commas. If a later portal version uses separate entries/chips, add all three individually. A saved form alone does not prove the authorization request is correct.

Why "Request body parameters"? Slack's published OAuth metadata specifies client_secret_post. This sends the client credentials in the HTTPS token request body, rather than an HTTP Basic header. The token and refresh endpoint are the same Slack URL.
  1. Review the tenant restriction, URLs, credentials, and scopes. Select Save.
  2. Copy the resulting OAuth client registration ID into the personalization panel. Do not substitute your Slack App ID or Client ID.

"Any Teams app" is an app-binding setting, not a request to create a Teams app. Keep the organization restriction to My organization only for this pilot. Existing registrations and portal controls can differ; verify against current Microsoft guidance.

05
Microsoft 365 admin center / custom federated connector

Create the Copilot connection

Go to Microsoft 365 admin center > Copilot > Connectors > Gallery > Created by your org > Create a new connector > Connect to MCP server > Add. You can draft name/description early; the OAuth registration must exist before you finish the authenticated setup.

Connector fieldYour valueCopy
Publisher and legal metadata require review. The default developer and legal links identify Slack's hosted service for a private lab, not a Slack-certified Copilot integration. Slack's privacy policy excludes third-party integrations. These links do not establish coverage for your organization's custom integration or Microsoft processing. Replace/approve applicable developer details and notices in the personalization panel before a customer rollout; do not use placeholder Contoso URLs or claim to publish on Slack's behalf.

Choose OAuth 2.0, not "No Auth" or Microsoft Entra SSO for this direct Slack endpoint. The URL is https://mcp.slack.com/mcp, not an app.slack.com/client/... workspace/channel URL.

Review the connector notice yourself before accepting it. Scope availability to the pilot account wherever the wizard offers rollout controls. If availability is configured only after creation, coordinate existing tenant access controls first, then immediately restrict staging; do not assume a new connection starts private. Select Create or Save only after that review.

06
Governance + first user connection

Stage the pilot, then connect as the user

  1. Open Copilot > Connectors > Your connections > . Under Staged rollout, select only or an approved pilot group. Do not select "Deploy to all users" for the lab.
  2. Check Agents > Settings > Agent and plugin access and the custom connector's individual state. Custom connectors are in the "built by your organization" category. Ensure the connector is enabled/unblocked without broadly enabling unrelated connectors.
  3. Check Agents > Settings > User access. This is a tenant-wide ceiling: staging does not override it. The pilot user must be allowed by both controls and have the required Copilot license.
  4. Allow up to 10 minutes for documented propagation. As , open Microsoft Copilot Chat > ... > Settings > Sources > > Connect.
  5. During Slack OAuth, verify , the intended Slack user, and the requested permissions. Review any installation/reinstallation approval before accepting. A bot installation by an admin is not proof of this user's authorization.
  6. Return to Copilot and start a fresh conversation. Inspect the available tools, where the UI exposes them; verify no write/private/DM access was accidentally requested by this pilot configuration.

08
Failure-driven troubleshooting

Diagnose the boundary that actually failed

Slack says the app is not enabled for MCP server access

This is an explicit app-level access gate, not evidence that the OAuth token is invalid. Open the internal app's /app-assistant settings page using the personalized link in step 02 and enable Slack MCP server access. Review any plan, permission, or installation requirements shown there instead of adding unrelated scopes. Retry discovery after enabling; a successful tool list and a real Copilot retrieval are still needed to demonstrate the full integration.

OAuth form will not save

Check all required fields, HTTPS URLs, exact Client ID/Client Secret, tenant restriction, and scope control formatting. The client secret is entered directly from Slack. Saving does not validate the whole token exchange. Do not troubleshoot by pasting credentials into chat or public token decoders.

Slack reports redirect mismatch, invalid client, or invalid scope

Compare the exact callback, including casing and path, with step 03. Confirm Slack Client ID (not App ID), current client secret, user-only authorization endpoint, and the three scopes under User Token Scopes. Review any pending scope reauthorization. Use the exact error text and redact secrets before sharing it.

401/403 or token-exchange failure

Confirm the authorization and token endpoints from Slack's metadata, client_secret_post / Request body parameters, and the pilot's app/workspace approval. If there are IP restrictions, check Microsoft's documented federated-connector egress requirements. Refresh failures require examining the actual refresh response and rotation configuration; a saved OAuth registration is not proof that refresh works.

Connected, but tool permissions fail to load or no Slack tools appear

A connected label is not proof of usable MCP access. Inspect the failed discovery operation's sanitized Response: the browser request can return HTTP 200 while the body reports MCP tool discovery failed and responseCode: 500. That does not identify a Slack-side root cause. Confirm the three User Token Scopes and the Microsoft portal's comma-separated Scope input first. If you correct the registration, save it, disconnect only this Slack source in Copilot, then reconnect and review consent to replace the stored connection. Retry tool discovery in a fresh conversation. Keep the existing app and connector; do not add permissions or switch off authentication blindly. If failure persists, capture the exact error, UTC time, and request/correlation ID for further diagnosis; never share headers, tokens, authorization codes, or a full HAR.

Registration ID accepted, but no tools or 404 on calls

Check that the endpoint includes /mcp, is Streamable HTTP, and matches the registered base URL. Confirm the OAuth registration was not bound to a specific Teams app. Slack does not support Dynamic Client Registration or the older SSE transport for this server. Capture a sanitized error; do not substitute a shared bot token or disable authentication.

Connector does not appear in Copilot Sources

Verify the same tenant and pilot identity, Copilot license, connector enabled/unblocked state, staged rollout, and tenant User access. Publisher-type controls and individual enablement must be considered together. Allow the documented propagation window, refresh Copilot, and start a new conversation.

Connected, but search is empty or irrelevant

First search for the exact synthetic marker in Slack itself. Verify workspace, current user, granted scopes, recent accessible content, and retention. Use keyword queries first. Slack's Real-time Search documentation distinguishes semantic/AI Search eligibility from keyword fallback; that distinction does not by itself prove hosted-MCP access for your plan. Honor rate-limit Retry-After guidance rather than retrying aggressively.

Can we host it in VS Code instead?

VS Code can be an MCP test client or a development environment for a custom server. GitHub Copilot in VS Code is a different client from Microsoft Copilot. A local stdio server or localhost URL is not directly reachable by Microsoft 365. A custom adapter needs an authenticated cloud-reachable HTTPS endpoint, per-user authorization, approved hosting/tunneling, and its own lifecycle. Build it only after identifying a concrete limitation of the hosted route.

Cleanup without changing unrelated services

Disable or delete only this pilot's custom connector in Your connections, as approved. Remove the specific OAuth registration and Slack app/grants if no longer needed, after checking dependencies. Revoke exposed bot/app tokens even though this route does not use them. Removing a local guide/device save does not revoke tokens or delete cloud resources.
